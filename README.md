# Hiver SDE Intern Take-Home — AppleSupport Twitter Agent

**Read this first:** I built this against a 100-row sample of the
Customer Support on Twitter dataset, not the full ~3M-row Kaggle set —
Kaggle isn't reachable from the sandbox I built this in. Every number in
this repo is real and reproducible, but the golden eval set is **17
examples**, not the 150–250 the brief asks for, because that's every
usable AppleSupport-directed message in the sample. `report.md` (section
4) and `decision_log.md` (#1) go into exactly what that costs. Everything
else — taxonomy, pipeline, retrieval, escalation logic, eval harness,
judge, baselines — is built to the full spec and scales directly; only
`n` changes once real data is dropped in.

## What this is

An AI support agent for **AppleSupport** (picked because it had the most
data in the sample: 13 historical public reply threads, all clustered
around the iOS 11 update). Given an inbound customer tweet, it:

1. Classifies intent into one of 8 categories I derived from actually
   reading the traffic (`src/intents.py`).
2. Drafts a reply grounded in the brand's 3 most similar historical
   replies, retrieved via TF-IDF (`src/retrieval.py`, `src/reply_gen.py`).
3. Decides auto-handle vs. escalate-to-human, with a stated reason
   (`src/escalation.py`).

## Reproduce the headline results (~10 seconds, no API key needed)

```bash
pip install -r requirements.txt   # stdlib only for the default path; see below
python3 run_demo.py
```

This runs the pipeline against `data/golden/golden_eval.csv`, compares it
to two baselines, and writes:
- `outputs/predictions.csv` — every prediction, per example
- `outputs/eval_summary.md` — accuracy, per-class report, confusion
  matrices, reply-quality judge scores, and judge/human agreement

Headline numbers (n=17, see the scope note above):

| | Intent accuracy | Decision accuracy |
|---|---|---|
| **System** | **0.82** | **0.88** |
| Trivial baseline (predict majority class always) | 0.29 | 0.59 |
| Simple keyword baseline (2 keywords, no priority) | 0.41 | 0.65 |

Reply quality (4-check rubric, heuristic judge): 0.96/1.00 average,
82–100% agreement with hand-scored human labels per check — and the
disagreements are actually more interesting than the agreements. See
`report.md`, failure mode 5.

## Optional: run with Claude instead of the offline fallback

```bash
export ANTHROPIC_API_KEY=sk-...
pip install anthropic
python3 run_demo.py
```

With a key set, `src/intents.py`, `src/reply_gen.py`, and `eval/judge.py`
switch from their deterministic rule/template/heuristic fallback to
calling Claude, same interfaces, nothing else changes. I did this on
purpose (decision_log.md #8): the brief says the code won't be run on
the full dataset and has to reproduce in under 15 minutes, so the default
path can't quietly depend on a key that might not be there when this
gets reviewed. The LLM path is real and wired up, just not required for
the numbers above.


## Golden set methodology

I took every customer message in the 100-row slice that @-mentions
AppleSupport (or its alias handle in this thread), whether or not it got
a public reply in-sample — 17 total. That's a census of the slice, not a
sample of it; there wasn't enough data left over to actually sample from.
At real scale, the right move is stratified random sampling once a
first-pass taxonomy exists, oversampling the rare/high-risk intents like
account/billing — see decision_log.md #1.

I labeled it myself, reading each message against the taxonomy in
`src/intents.py` and writing down the intent, the correct auto-handle vs.
escalate call, and a note on anything I wasn't sure about. A few of those
notes flag genuine judgment calls (tweet 119272, for one) rather than
pretending the call was obvious. No second labeler was available at this
n — `report.md` says what that costs the "how good is this really"
argument, because it's a real cost.

## Cite anything you borrowed

Nothing beyond stdlib (csv, re, math, hashlib) and, optionally, the
`anthropic` Python SDK. The TF-IDF/cosine retrieval is written from
scratch rather than pulled in from scikit-learn — the dataset here is
small enough that it's a ~30-line implementation, and it keeps the
dependency footprint at zero for the default no-API-key path.
